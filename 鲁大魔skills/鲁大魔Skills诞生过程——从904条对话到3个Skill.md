## 二、蒸馏全流程：三层递进

### 第〇层：素材准备——Get笔记提取+分场景写标题

904条连麦对话，首先用Get笔记提取内容，按14个场景组分条目，每个条目写好标题。这一步只是把原始对话变成可处理的Markdown文件，没有做任何抽取。

### 第一层蒸馏：条目拆解——从对话中挖出隐藏内容

单纯对话本身表达不出什么。每条对话背后藏着：

- **回答方式**：鲁大魔怎么回应的，用的是什么语气、什么武器
- **问题判定**：这个问题成不成立，为什么不成立
- **问问题人的思维**：他为什么这样问，他在逃避什么
- **拉出方式**：鲁大魔怎么把人从错误思维里拉出来
- **解决方式**：鲁大魔解决真实问题的方法是什么

对每条LD做了L1-L5逐层分析（拉出原句→判断自知→判断锁型→识别武器→提取观点），形成：

- **OPI 857个**：每条LD至少1个核心观点
- **CAS 71个**：具体商业案例/事件/数据
- **SOL 12个**：可执行的操作步骤/路径

同时建立跨条连接：
- **1649条连接**，覆盖614个文件
- LD-001(266条引用)、LD-003(155条引用)、LD-004(120条引用)为三个标杆对话

#### 2.2 区分有效问题 vs 无效问题 + 统计比例

| 区间 | 自知范围 | 人数 | 占比 |

无效问题的五种典型：前提缺失型(~60条)、外包决策型(~15条)、数据造假型(~10条)、对抗大势型(~5条)、纯发泄型(~4条)。

有效问题的四种典型：精准诊断型(~120条)、方案验证型(~80条)、归因困惑型(~50条)、认知求真型(~34条)。

#### 2.3 五大模式——鲁大魔怎么解决

根据自知光谱精确匹配五种锁型（即五大解决模式）：

| 锁型 | 人数 | 适用自知 | 核心机制 |
|------|------|---------|---------|
| **破锁** | 114 | 0%-30% | 不回答表面问题，直接宣告前提不成立 |
| **炸锁** | 236 | 30%-50% | 强力打断循环→拆掉旧框架→装回去 |
| **硬锁** | 215 | 30%-50% | 宣告级力度封死回头路→不给第三条 |
| **翻锁** | 229 | 50%-70% | 先共情→翻转框架→给建设性新路 |
| **软锁** | 101 | 70%-100% | 确认判断→加保细节→温和引导 |

无效问题→破锁/前提击穿。有效问题→翻锁/软锁。半有效问题→炸锁/硬锁。

#### 2.5 背后思维分析

**用户问问题的思维模式**：
- 外部归因（行业不行/别人搞我/运气不好）
- 身份归因（我不适合/我缺勇气/我是XX类型的人）
- 跳过阶段（想从1.0跳到3.0）
- 用多数人意见替代价值判断
- 用复杂计划逃避简单执行

**鲁大魔解决方式的思维模式**：
- 不对称回应：77.2%从不正面回答，从不与问题在同一层相遇
- 最小接触面：压缩到1个不可再分解的物理事实
- 行为高于语言：不听说什么，只看做什么
- 自知决定一切：问题质量在第一句话就已决定

#### 2.6 拉出方式——怎么把人从错误思维里拉出来

6步回应弧线：
```
Phase 1: 破锁 → "你说的不是问题——真问题是……"
Phase 2: 诊断定位 → 瓶颈定位/归因翻转/变量压缩
Phase 3: 概念区分 → 把混着的切开→困惑自消
Phase 4: 阶段归位 → "你在X——应归到Y——先做Y"
Phase 5: 行动路径 → 压缩成明天能做的第一个动作
Phase 6: 关闭 → 行为证据/叙事翻转/逆向推到底
```

### 第三层蒸馏：底层规律——从模式到元规则

第二层蒸馏产出了11种问题类型、5种解决模式、10种思维工具的统计分布。第三层的任务是从这些模式中再剥一层——总结出更底层的规律。

#### 3.1 商业三表（SYS-005）

概念表·关系表·流程表。12个词的概念翻转（你以为→实际），11条反直觉原则，5个执行流程，14项自查清单。

核心发现：12个概念（生意/供应链/需求/产品/流量/筹码/阶段/瓶颈/团队/环境/利润/学习），每一个的定义都不是普通人的理解。

#### 3.2 十二条元规则

从全量统计的分布形态本身反推：

```
约束层（不可变）：
  1. 情不立事 — 企业是盈利组织，不是情感共同体
  2. 行为证据 — 不听说什么，只看做什么
  3. 规则大于钱 — 付费=入场券≠被回答权

系统层（可配置）：
  4. 第一性原理 — 剥到底，问五次为什么
  5. 阶段归位 — 你现在在第几阶段就做第几阶段的事
  6. 变量压缩 — 任何复杂问题只有2-3个关键变量
  7. 环境决定 — 你身边的人=你的天花板
  8. 筹码先于策略 — 没有筹码=策略是空谈

操作层（可执行）：
  9. 概念区分 — 把搅在一起的词拆开
  10. 证伪思维 — 不做分析，做一个可证伪的小动作
  11. 叙事翻转 — 同一事实换框架=力量翻转
  12. 下去 — 切断无效交互，不浪费彼此时间
```

## 五、踩过的坑

### 坑1：结构由我决定，不是由内容决定

一开始我在规划"做一个skill还是四个skill"、"路由怎么设计"——这些都是从我的判断出发。用户纠正：**产品不是根据我决定的，是根据内容决定的**。之后所有结构设计都改为：先读SYS文件，看内容本身的组织结构，再让结构跟随内容。

**教训**：做知识库类skill时，结构的权威来源是内容本身——不是产品直觉。

### 坑2：语言规则不能抽象化

我第一次写语言规则时，从SYS-001提炼了7条抽象规则（不用抽象词、不做心理按摩……）。用户纠正：**去看看鲁大魔回答方式**。实际是：13种问题类型各有各的第一刀句式、武器组合、语言风格——不是7条通用规则。

**教训**：知识蒸馏的最后一层不能是抽象规则——必须是按类型的、可操作的、带例句的。

### 坑3：差点改错文件

把SYS-004当成SYS-005去改。用户立刻叫停："你改错了，刚刚那个不需要改"。已改的内容恢复了，没造成永久损失。

**教训**：操作前确认目标文件ID。

### 坑4：入口判断——没有考虑"人家在打招呼"

第一版/连麦没有入口判断——不管用户说什么，直接提取4信号、判定13型。用户抓住："不能人家一介绍自己就挨骂吧"。于是加了入口判断：打招呼→不判定→正常回应。

**教训**：Skill的入口逻辑和核心逻辑是两层——入口先判断"该不该触发"，然后才是核心能力。

### 坑5：入口太生猛——没有考虑"等人把话说完"

入口判断第二版回应"你好。卡在哪。"——虽然不判定类型了，但太生猛。用户纠正：**要有可用性，等人把话说完，了解清楚再开搞，耗的是用户的时间**。于是入口判断重写为三层：第一句接住→信息不够就引导→够了才进入诊断。鲁大魔的生猛保留在诊断阶段，入口阶段是温和的。

**教训**：鲁大魔本人直播时对方已经排队上麦——场景不同。Skill的使用场景是"随手点进来、试探、没想清楚"，入口需要引导而非即判定。**开头的温和是为诊断铺路，不是全程温和**。

### 坑6：Windows符号链接需要管理员权限

计划用 `New-Item -ItemType SymbolicLink` 把E盘文件链到C盘skills目录，但Windows拒了——需要管理员权限。解决：改用 `Copy-Item` 复制，后来用 `bash cp` 同步。

**教训**：Windows上符号链接不是默认可用的。部署策略用复制而非链接。

### 坑7：don't ask模式下的Write工具被拒

会话处于don't ask模式时，对C盘路径的Write直接被拒。解决：用Bash的cp绕过——或者切回auto模式。

**教训**：don't ask模式会限制某些路径的写操作，bash cp可以兜底。

### 坑8：PowerShell多行粘贴被截断

用户粘贴多行命令时PowerShell把换行当成分隔符执行，导致部分命令失败。解决：给单行命令。

**教训**：给用户的PowerShell命令必须单行，不能依赖换行。
